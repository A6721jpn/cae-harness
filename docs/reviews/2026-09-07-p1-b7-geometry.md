## Implemented contract

- `GeometryIntent` is an immutable, slot-based value with exactly nine required fields: `source_step_digest`, `geometry_digest`, `inspection_digest`, `body_id`, `step_unit`, `placement`, `body_evidence`, `unit_evidence`, and `placement_evidence`. `SCHEMA_VERSION` is the existing canonical version `"1"`; `GeometryValidationError` is the only new validation exception.
- The three lowercase SHA-256 fields retain distinct roles: original STEP bytes, the declared geometry revision, and the inspection-record bytes. They are not computed from one another and are not required to differ. A body ID is source-scoped and is not inferred from a geometry digest or body naming convention.
- `body_id` must be a typed `BodyId`; `placement` must be the existing explicit `RigidTransform`; and the declared `step_unit` must be a supported registry unit with length dimension. The exact source spelling, such as `mm` versus `m`, remains in canonical identity. No unit is inferred, defaulted, or silently substituted.
- The three required `EvidenceRef` values are field-bound to `geometry.body_id`, `geometry.step_unit`, and `geometry.placement`. The placement preserves the existing source/target frame and translation-frame invariants. Nested translation values use the shared SI projection; the declared STEP unit is not applied a second time.
- `to_dict()` and `to_bytes()` use the shared canonical owner. Construction validates the complete nested projection, so unrepresentable placement translation overflow/underflow is rejected while the value is created. No STEP parser, inspection result schema, registration lookup, freshness check, readiness checker, cross-object `CaseSpec` validation, or generated rigid-tool selection is introduced.
